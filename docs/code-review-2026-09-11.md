# 项目审查与结构优化（2026-09-11）

首次审查时项目是 C++17 + SDL2/OpenGL 3.3 的 RA2 沙盒。资源解析、建筑、载具、武器和渲染已有模块划分，
但主入口仍集中处理生产、部署、输入和场景编排，部分游戏逻辑与 OpenGL 依赖混在同一编译单元。
本轮优先修复可验证的问题，拆出寻路和公共构建目标，并建立回归测试入口。

## 已处理的问题

| 级别 | 问题及影响 | 处理 |
| --- | --- | --- |
| 高 | 无限地图上的 A* 没有工作上限；目标被围住时可能一直搜索，阻塞主线程 | 抽出 `pathfinding`，限制节点扩展数，跳过过期队列节点，并保护极端整数坐标的邻格运算 |
| 高 | `canWalkOn` 无条件允许目标格，导致“寻找附近空地”的分支失效，坦克可以走进已占用终点 | 只豁免本单位起点的占用，已占用终点先解析为附近空闲格 |
| 高 | SHP 只检查输入长度，没有检查帧矩形是否超出输出画布 | 在写入前检查矩形、数据偏移、行长度及游程边界 |
| 高 | TMP 偏移加法与像素乘法在 32 位整数中溢出，可能错误通过检查并越界写入 | 提前验证文件区间，使用宽整数计算像素数，分配前检查载荷和容量 |
| 中 | SHP 将长度为 4 的压缩行一律当作透明行，合法的两个像素被丢弃 | 统一按零值游程解码，从实际像素生成连续可见区间 |
| 中 | SHP 把压缩类型后的填充字节一起参与类型判断，真实 `gapowr_b.shp` 中的 `0xCCCC0003` 被拒绝 | 仅使用低字节作为压缩类型，同时保留原始元数据 |
| 中 | 新生成的爆炸效果立即累加整个帧间隔，跳过开头动画；长帧时可能直接消失 | 旧效果正常推进，新效果只计入落地后剩余的时间 |
| 中 | 开火位置排序使用 epsilon 决定是否比较第二关键字，不满足严格弱序 | 对距离使用明确的第一、第二排序关键字 |
| 低 | 血条图片裁剪后创建了新纹理，但原纹理未释放 | 裁剪函数接管原纹理并在替换后释放 |

SHP 修复兼容项目资源中超出奇数行宽的**末尾透明填充**；它不写像素，因此允许截断。
内部游程越界、超宽可见像素和不完整游程仍会报错。
压缩类型字节与零值游程的核对参考了
[OpenRA 的 SHP 加载实现](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Mods.Common/SpriteLoaders/ShpTSLoader.cs)，
最终兼容性以本项目实际资源的批量解码结果为准。未改动原有 SHP 实验解码器。

## 结构改动

- `ra2_core` 隔离不依赖图形系统的资源和寻路逻辑，可单独构建与测试。
- `ra2_ui_backend` 集中编译第三方图形后端；`ra2_engine` 共享游戏和渲染实现。
- 统一 SDL 程序链接及运行库复制，空 DLL 列表不再触发无效复制命令。
- 删除 `updateRhinoUnit` 中无条件 `return` 后的整段旧移动实现，以及该文件中未使用的辅助函数。
- 新增 CTest 测试和可选隐藏窗口启动检查，详细用法见 [代码结构](code-structure.md)。

## 验证

- 三个程序目标均通过 MinGW Debug 构建。
- Debug 的五组 CTest 检查通过：解码边界、寻路、资源批量解码、游戏逻辑、主程序启动。
- 独立核心模块通过 MinGW Release 构建及三组检查，确认不需要 SDL/OpenGL 也能验证核心逻辑。
- 独立核心模块另经 MSVC AddressSanitizer 构建，三组检查通过，未报告内存访问错误。
- 批量成功加载 526 个 SHP/VXL/HVA/VPL/PAL 资源文件，解码 8,718 帧 SHP。
- 单独编译 Git 原版本验证：短行像素、爆炸计时、已占用终点三项在旧实现失败，在修复后通过。
- 启动检查实际运行主程序的资源加载、OpenGL 渲染三帧及清理退出；未覆盖完整交互流程和人工画面检查。

## 尚待处理的设计问题

1. **动态占用冲突**：路径规划后若另一辆车或建筑占据后续路径，移动过程没有重新检查。
   `MapGrid::Cell` 只保存 `occupied` 布尔值，没有占用者身份和下一格预留，存在重叠和错误释放占用的风险。
   修复应同时覆盖战车工厂内的特殊出厂路径，不能简单将所有已占用格禁止通行。
2. **寻路能力边界**：当前同步搜索在预算耗尽时返回失败；对已占用终点选择最近空闲格，
   不保证那个候选一定可达。大量单位、超长路径需要分帧调度和更完善的终点候选策略。
3. **入口职责过多**：`app_main_ui.cpp` 仍超过 1,700 行。后续可依次拆出生产、MCV 部署和输入命令处理，
   每次以相应状态机测试保护行为。
4. **纹理所有权**：`UiTexture` 仍可复制原始 OpenGL 句柄，各模块手工清理；资源加载中途异常时的完整回收
   尚未系统验证。后续适合引入不可复制、可移动的纹理所有权类型，并保证在 GL 上下文销毁前释放。
5. **配置读取成本**：`ArtIni::building/animation` 每次重新读取整个文件；可在加载时建立节索引，
   但需先明确是否保留运行中修改配置的行为。

编译器仍报告部分既有的未使用函数和忽略返回值警告。建筑缓存的两处“可能悬垂引用”警告已人工检查：
当前返回值来自静态缓存，不依赖传入的临时路径生命周期，未作为已确认的 Bug 处理。

以上是本轮检查范围与结果，不代表全部玩法、异常路径或所有二进制格式均已穷尽验证。
