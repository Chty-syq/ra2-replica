# 建筑血条与基地车展开回归修复

日期：2026-09-15。

## 原因与修复

建筑血条在迁移到 World 后直接使用规则中的真实 Strength 计算长度，
遗漏了旧版按占地保证显示宽度的处理，因此发电厂、建造厂等血条明显缩短。
现在由 `presentation/building_health.h` 单独计算血块：恢复原来的占地尺寸下限，
按 `hp / maxHp` 填充，仍显示真实血量比例，不再通过增大建筑生命值实现显示长度。
原有颜色、倾斜像素样式、位置以及选中/悬停入口继续使用。

基地车转换目标类型时原先调用 `components(..., false)`，使建造厂直接进入完成态，
跳过了全部展开 SHP 帧。现在基地车对准展开方向后，立即转换为正在施工的目标建筑，
通过同一套建筑动画流程依次播放展开帧，再进入工作动画；移除了转向之后等待固定 90 帧的空挡。
同一实体 ID、生命值比例、占地与选中关系沿用，盟军和苏军共用这套流程。
收起仍使用逆序施工动画与既有 `DeployFrames` 计时。

本次是恢复已实现的表现。施工仍使用当前 `BuildupTime` 名义总时长，
没有在此轮引入原版 SHP 逐帧取整校准。

## 验证

- `gameplay_regressions` 增加不同占地的满血、半血、残血及无效血量边界检查。
- 盟军/苏军基地车覆盖转向、展开起始帧、中间帧、完成、逆序收起和单位身份保持。
- 新增 `demo_building_presentation`，实际加载两阵营建造厂 SHP，并验证展开、完成和收起阶段。
- Debug 主程序、渲染实验及测试目标构建通过，12 项 CTest 通过。
- 检查实际 OpenGL 输出的发电厂血条、两阵营展开首帧、中间帧、完成及收起画面。

图形回归可运行：

```powershell
./cmake-build-debug/ra2_power_demo.exe --building-smoke-test ./cmake-build-debug/building-fix.bmp
```

可选输出路径会生成第 1、20、47、73、74、145、191 游戏帧的 BMP。
这些是隐藏窗口的自动回归场景，不能用其界面帧率作为性能测量。
