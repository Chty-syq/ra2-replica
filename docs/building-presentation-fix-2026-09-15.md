# 建筑血条与基地车展开回归修复

日期：2026-09-15。

## 原因与修复

建筑血条在迁移到 World 后直接使用规则中的真实 Strength 计算长度，
遗漏了旧版按占地保证显示宽度的处理，因此发电厂、建造厂等血条明显缩短。
现在由 `presentation/building_health.h` 单独计算血块：恢复原来的占地尺寸下限，
按 `hp / maxHp` 填充，仍显示真实血量比例，不再通过增大建筑生命值实现显示长度。
原有颜色、倾斜像素样式、位置以及选中/悬停入口继续使用。

基地车转换目标类型时原先调用 `components(..., false)`，使建造厂直接进入完成态，
跳过了全部展开 SHP 帧。现在基地车对准展开方向后，立即转换为正在施工的目标建筑，
通过同一套建筑动画流程依次播放展开帧，再进入工作动画；移除了转向之后等待固定 90 帧的空挡。
同一实体 ID、生命值比例、占地与选中关系沿用，盟军和苏军共用这套流程。
收起仍使用逆序施工动画与既有 `DeployFrames` 计时。

本次是恢复已实现的表现。施工仍使用当前 `BuildupTime` 名义总时长，
没有在此轮引入原版 SHP 逐帧取整校准。

- 盟军/苏军基地车覆盖转向、展开起始帧、中间帧、完成、逆序收起和单位身份保持。
- 新增 `demo_building_presentation`，实际加载两阵营建造厂 SHP，并验证展开、完成和收起阶段。

- 检查实际 OpenGL 输出的发电厂血条、两阵营展开首帧、中间帧、完成及收起画面。

```powershell

```

这些是隐藏窗口的自动回归场景，不能用其界面帧率作为性能测量。

## 2026-10-17：巨炮贴合与基地收起操作

巨炮原先将 `TurretAnimZAdjust=-60` 换算成模型空间的物理高度，使炮塔在基座上方悬空。现在保留 `TurretAnimX/Y` 的屏幕定位与 VXL/HVA 自身变换，移除额外抬高；建筑炮塔也不再继承坦克调试面板的缩放和倾斜。已检查八方向的实际 OpenGL 画面，炮塔底部保持与基座贴合。深度仍沿用现有建筑炮塔排序策略，并未在此轮实现完整原版 ZAdjust 深度算法。

基地收起操作的问题发生在建筑选择：原先只检测地面占地，基地楼体与吊臂伸出占地上方的可见部分不能被点中。现在为建筑纹理保存每像素一位的命中掩码，优先检查当前显示的主体、工作层及施工／收起帧，再回退到地面占地。透明画布和未显示的生产层不会拦截点击。通过楼体选中基地后，再次点击或按 D 可以收起，保持原基地车的实体身份。

`gameplay_regressions` 补充两阵营基地占地外可见像素、透明边缘、选中后收起及车辆身份保持检查。`demo_building_presentation` 改用实际 SDL 鼠标和键盘事件：盟军点击楼体选择并再次点击收起，苏军点击楼体选择后按 D 收起；不再由测试直接发送收起命令。场景运行 208 个逻辑帧，关键帧截图入口不变。

本轮 Debug、Release 构建均成功，CTest 各 22/22 通过。对照及八方向预览保存在忽略目录 `build/visual-fixes`。

## 2026-10-17：光棱塔 / 磁暴线圈预览闪退

两份系统崩溃报告均为 `EXC_BAD_ACCESS`，地址 `0x8`；LLDB 可复现到 `drawBuildingInstance` 的 `layerTexture.width`。根因是上一轮新增的 Fire 层在预览、待机、动画结束或断电时合法返回 `nullptr`，主体绘制和车辆遮挡重绘却只判断了纹理列表非空，仍然解引用返回值。两个绘制入口现在统一跳过该帧隐藏的层，同时保留建筑主体、待机层与实际蓄能动画。

原 `demo_defense` 将所有塔固定为蓄能第 27 帧，因而没有覆盖空 Fire 层。现增加三种地形中预览、待机、动画结束和断电的实际绘制，以及车辆遮挡重绘；并通过 SDL 鼠标事件实际点击侧栏、分别预览和放置光棱塔 / 磁暴线圈，运行 240 帧验证施工、完工、开火、停电与恢复供电。

用户同时提供的 CapsLock / IMK 日志没有出现在实际故障栈中，本次修复针对项目渲染空指针，不改动系统输入法行为。复现栈和修复后日志保存在忽略目录 `build/defense-crash-fix`。

修复后 Debug / Release 均已重新构建，完整 CTest 各 33/33 通过，包含扩展后的防御塔 SDL 建造与断电恢复回归。

## 2026-10-18：建筑维修与售卖

侧栏扳手、美元按钮现在对应真实模拟命令。点击扳手后，点击己方受损建筑开始持续维修，再次点击同栋建筑取消；可同时维修多栋建筑。资金不足时暂停扣费和回血，资金恢复后继续，修满自动停止。右键或 Esc 只退出当前工具模式，已开始的维修继续运行；两个工具互斥，点击建造图标也会退出工具模式。

维修读取原版 `RepairPercent=15%`、`RepairRate=.016`、`RepairStep=8`：按 900 游戏帧 / 分钟换算为每 14 游戏帧最多恢复 8 HP，费用按实际补量、原价和最大生命值折算，整数向下取整，非零成本至少收取 $1。原版 `Repairable` 和 `ClickRepairable` 分别控制工程师维修能力与侧栏维修能力。费用逐步支付，沙盒模式仍使用真实维修费用；维修状态归模拟所有，与绘制 FPS 无关。

点击美元按钮后，点击己方已建成且允许售卖的建筑，播放其原版建造动画的逆序。动画结束才移除建筑、释放占地与墙体碰撞、返还资金；进入售卖状态即停止生产、武器和电力供需。返款为 `Cost × RefundPercent × HP / Strength`，默认满血返原价 50%，在结束时按剩余血量结算。售卖途中被摧毁不返建筑款，同一实体不会重复结算；无建造动画的围墙直接移除。

工厂未出厂的付费生产队列在开始售卖时取消并退款；正在出厂时要求先等车辆驶离，避免把单位夹在拆除动画中。矿场售卖后，矿车保留货物、重新寻找可用矿场。遵守 `Unsellable`，敌方、中立驻军建筑、载具以及施工 / 收起中的建筑不可直接用此工具售卖。建筑被工程师占领或收起时，旧维修状态不会继续扣费。本轮实现侧栏建筑操作；维修厂修理载具、出售后的额外步兵产出和操作音效仍属后续机制。

维修中显示原版七帧 `wrench.shp`，缺钱时闪烁并保留血条；光标使用原版 `mouse.shp` 的维修 170–189、禁止维修 190、售卖 129–138、禁止售卖 149 帧，均配 `mousepal.pal`。悬停提示当前维修费用、取消操作或预计售卖返款。macOS 补充系统中文字体候选，状态面板限制宽度并自动换行，避免文字恢复后遮挡地图交互。

行为结构参考 [OpenRA RepairableBuilding](https://github.com/OpenRA/OpenRA/blob/release-20231010/OpenRA.Mods.Common/Traits/Buildings/RepairableBuilding.cs)、[Sellable](https://github.com/OpenRA/OpenRA/blob/release-20231010/OpenRA.Mods.Common/Traits/Sellable.cs)，数值使用本项目原版 rules.ini；光标帧对照 [OpenRA RA2 cursors](https://github.com/OpenRA/ra2/blob/61e24e3c1d7b586aa55a86096d29e1559aa9b994/mods/ra2/cursors.yaml)。原版规则与素材文件没有改写。

新增 `building_service_regressions` 覆盖周期 / 费用、取消 / 修满、资金不足 / 恢复、权限、售卖中受击 / 被摧毁、逆建造时序、退款 / 重建、生产队列 / 出厂车辆、工程师占领、矿车重新寻找矿场、30 / 60 / 144 FPS 一致性。`demo_building_actions` 通过真实 SDL 鼠标和按键操作维修、取消、修满与售卖双方建筑，并验证光标及右键 / Esc 退出。使用 `ra2_power_demo --building-actions-smoke-test build/building-service/actions.bmp` 可导出关键帧，输出目录需预先存在。

最终验证：Debug / Release 构建成功，完整 CTest 各 35/35 通过，包含此前运输 / 驻军、防御塔预览和所有步兵 / 载具回归。两份新增 SHP 与 `assets_origin` 逐字节一致；关键帧、资源哈希及构建 / 测试日志在忽略目录 `build/building-service`。
