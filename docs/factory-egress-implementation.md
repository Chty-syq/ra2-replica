## 当前行为

生产计时结束后，工厂先检查完整通道。只要有地形、其他建筑、车辆或预留冲突，
完成的队列项目就保留并等待，既不生成实体，也不重复扣费。
通道可用时，通过统一创建入口在厂内生成车辆，预留整条路径，随后进入以下阶段：

| 阶段 | 行为 |
| --- | --- |
| Idle | 可以推进队首生产计时 |
| Blocked | 队首已经完成，但通道受阻；每 Tick 重试 |
| Preparing | 实体已创建，停在内部起点；等待配置的准备时间 |
| Driving | 使用通用车辆移动系统走完配置路径，速度、转向仍取单位定义 |
| Clearing | 车辆已驶离，工厂经过收尾时间后回到 Idle |

Preparing、Driving、Clearing 期间暂停下一项的生产计时。当前车辆驶离后停在出口；
如果它没有移走，下一项完成后会进入 Blocked。尚未实现工厂集结点。
这些排队与计时语义是当前演示规则，未声明等同原版多工厂生产规则。

出厂期间下达的移动、地面攻击、目标攻击或部署命令保留最后一条，在驶离后执行。
S 清除这条待执行命令，车辆仍会完成必须的出厂路径。出厂期间不主动执行射击。
驶离后部署仍受正常建筑占地检查约束，出口紧贴厂房时可能需要先移动到开阔处。
已生成的车辆从生产队列移除，取消生产不会退还它的费用。

## 配置

在 `assets/settings/replica.ini` 为工厂类型添加覆盖，不需要添加兵种分支：

```ini
[Factory.GAWEAP]
ExitPath=2:1,3:1,4:1,5:1
PrepareFrames=12
ClearFrames=6
```

路径是相对占地西北起始格的格坐标，包含厂内生成点和厂外结束点。
盟军、苏军当前都采用这条路线。以默认对战 6 档（60 游戏帧/秒）计算，准备 0.2 秒、收尾 0.1 秒；
驾驶时间由单位速度、转向和通道长度共同决定。上述数值均待原版实测。
未指定 ExitPath 的地面战车工厂会生成沿 +X 方向离开占地的默认路线，准备和收尾默认 0。

编译配置时拒绝非整数、非相邻步、重复格、离开后重入厂房、起点在外或终点在内的路线。
路径限制为 2～64 格，偏移在 -64～64 之间，阶段时间在 0～3600 Tick 之间。
错误携带覆盖文件名和行号。路线与 `foundationTiles` 共用当前建筑占地定义。
修改配置需要重启；没有引入运行时热重载。

## 状态和占格

`World` 分别保存建筑占地、车辆占格和通道/移动预留，地图查询看到三者的并集。
只有绑定该工厂且正在出厂的车辆能通过所属建筑的配置路径，建筑占地不会被临时清空。
`occupant` 优先返回格内车辆，`structureAt` 可独立查询同一格的建筑。

多个工厂按稳定实体 ID 顺序检查并预留通道，因此不能在同一 Tick 抢到同一出口。
车辆死亡释放自己的预留并通知工厂收尾；建筑死亡仅清理自己的占地，
幸存车辆继续沿已预留路线驶出。组件池发生重排后重新取得引用，避免创建新实体后的悬空引用。

## 表现层

只读快照携带工厂阶段、出车周期起点及工厂/车辆的双向 ID，表现适配器不推进生产。
渲染入口据此把正在出厂的车辆插入所属工厂底层与屋顶层之间；普通路过车辆不会触发生产图层。
工厂被摧毁时，幸存车辆转入普通绘制路径，避免因找不到父建筑而消失。

苏军工厂在准备、驾驶和收尾阶段切换 `ProductionUnderUnit` / `ProductionOverUnit` 图层。
生产专属动画从当前出车周期起点计时；建筑绘制与前景遮挡重绘共用 `buildingLayerTexture`。
普通工作动画仍用建筑自身时钟。附近车辆触发前景重绘时，也使用当前生产图层，避免覆盖回静态楼体。

保留当前 `_1`、`_2` 的图层资源组合，没有把损坏状态帧当作开门动画播放。
独立门体动画、维修、停靠、断电等状态仍需要后续机制及资源验证。
本轮截图检查验证当前项目的图层衔接，没有替代原版截图/录像对照。

## 首次接入验证结果（2026-09-11）

- `factory_egress_regressions`：内部创建、准备等待、完整阶段、占地不变、外部侵入/放置/地形编辑阻塞、通道释放。
- 同一工厂连续队列、两工厂反向争用同一出口、堵塞恢复、已出车项目不能再退款。
- 出厂中途停止、最后命令覆盖、攻击延迟、配置长通道后基地车部署。
- 车辆死亡、工厂死亡后幸存车辆继续驶离及占用清理。
- 路线校验、错误来源定位、30/60/144 Hz 与长帧驱动的一致性。
- `gameplay_regressions`：表现适配的关联、非出厂车辆排除、生产时钟和普通工作时钟。
- `demo_simulation`：真实 SDL/OpenGL 资源加载、部署/战斗/内部出车的联动检查。

MinGW GCC 13.1 Debug 三个程序构建成功，8 项 CTest 通过；Release 无图形构建 5 项通过。
MSVC 19.50 AddressSanitizer 全量重建后，5 项无图形测试通过。
MSVC 使用全量构建，以避免本机本地化编译输出影响 Ninja 头文件依赖缓存。
