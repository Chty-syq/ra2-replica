## 运行与操作

编译并运行 `ra2_power_demo`。初始场景包含发电厂、我方犀牛、我方基地车和一辆敌方灰熊。

- 左键选择我方单位，再左键空地移动；左键敌方单位执行攻击。
- 按住左键拖拽框选多个己方车辆；Shift + 框选增选，Shift + 单击增选或移除。框选松开只改变选择。
- 选中一组后，左键空地整组移动，左键敌人集中攻击；移动落点分配到目标附近的不同空闲格子。
- Ctrl + 左键整组强制攻击地面，S 整组停止；D 部署可部署单位，单选基地车/基地后再次点击也可展开或收起。
- 侧栏选择建筑后在空地放置；建好战车工厂后点击支持的车辆图标进入生产队列。
- 选中工厂可以查看进度、取消最后一项。出口受阻时保留完成项目，清空出口后继续生成。
- 车辆在厂内生成并沿配置通道驶出；出厂期间的新命令在驶离后执行，S 清除待执行命令。
- 右键取消选择/放置；Ctrl + D 切换调试面板。
- 左上角直接切换对战/单人速度档位，默认对战 6 档；同时显示逻辑帧率和绘制 FPS。
- 默认 `Sandbox=yes` 保留免费建造方式；车辆生产按 Cost、BuildSpeed 和 BuildTimeMultiplier 换算，不再固定为 120 帧。

飞机、舰船、采矿和特殊武器的机制尚未迁移，对应生产请求会显示不支持原因。
它们的素材仍保留，可以在独立 VXL 实验程序中查看。
切换调试面板的阵营改变建造栏和显示风格，不再把已有基地车直接改成另一个类型。

## 模块与权威状态

| --- | --- |

| `src/config/definitions.*` | 编译类型目录、单位/武器/弹丸/弹头引用、资源映射、能力限制及兼容参数 |
| `src/simulation/world.*` | EnTT 组件、稳定实体 ID、命令排序、固定步、移动/占用、战斗、生产、转换 |
| `src/presentation/world_view.*` | 只读值快照转换、位置插值、建筑动画阶段、炮口与弹道显示 |
| `src/interaction/unit_selection.*` | 点击/拖拽判定、己方车辆框选、增选与失效选择清理、整组意图提交 |
| `src/simulation/traffic.*` | 共享反向积分流场、多目标路线代价与优先聚拢的 Hungarian 落点匹配；车辆预测和同帧冲突由 `World` 统一裁决 |
| `src/foundation.*` | 模拟与渲染共享既有建筑占地形状，避免两边重复定义 |
| `assets/settings/replica.ini` | 项目资源目录、建筑图层与帧限制、暂定时间/速度换算 |

EnTT 固定为 `v4.0.0`，提交 `85c6bba014049b5de8fad49d25424df2f1f6a8c1`，
单头文件和 MIT 许可证随仓库保存，构建时不联网。
来源和 SHA-256 见 [依赖说明](../third_party/entt/README.md)。

主程序通过命令修改 `World`，不再调用旧的 `updateRhinoUnit`、`updateRhinoWeapon`、
`updateConstructionStates` 或单例基地车/出厂逻辑。旧辅助函数暂留给实验和回归测试。
`RhinoUnitState` / `BuildingInstance` 在新主循环中仅作为现有绘制函数的值适配对象，不能回写模拟。
单位类型由字符串 ID 和定义决定，添加同能力单位不需要新增 C++ 兵种枚举或行为分支。

2026-10-12：选中单位改为稳定 ID 集合，所有选中车辆都显示血条，界面显示组内数量。
框选区限制在地图视口内，侧栏和调试面板不触发框选；右键和窗口失焦取消进行中的拖拽。
整组移动通过一个 `GroupMove` 命令提交；模拟层优先认领点击位置周围的紧凑落点，绕障碍时共享流场，接近后进入各自停靠路线；交叉预测与窄道方向申请提前协调通行，见 [共享流场实现与验证](group-flow-field-2026-10-13.md)。其他组命令在同一逻辑帧以各自序列号执行，攻击保持同一个目标 ID。
验证包含 `unit_selection_regressions` 的反向框选、Shift 增删、归属检查、多单位到达/停止/攻击，
以及 `demo_group_selection` 的真实 SDL 鼠标事件与 OpenGL 框选显示。后者可通过
`ra2_power_demo --selection-smoke-test <输出BMP路径>` 保存框选、选中和到达时的截图。

## 已修复的行为问题

- 初始和生产犀牛统一为 `Strength=400`，灰熊为 300，发电厂为规则指定的 750。
- 删除建筑按外观占地放大生命值的规则。
- `Speed`、`ROT`、主武器、伤害、ROF、射程与装甲倍率来自各自定义。
- 犀牛和灰熊共用射击、命中伤害和死亡处理，车辆与建筑均可承伤。
- 占用与预留记录所属实体；目的地竞争、动态阻塞、死亡和转换不会清除其他实体的占用。
- 基地车转换按实例保存，生产出来的基地车也能展开/收起，保留稳定 ID 与生命值比例。
- 工厂分别保存队列；受阻出口不会重复扣费或重复生成单位。
- A* 使用整数代价和稳定平局顺序，不从阻塞的对角夹缝穿过。
- 每 Tick 共享 8,192 个寻路展开节点预算，按实际展开量扣除。
- 显示长帧最多追赶 120 个逻辑步，积欠时间保留，后续继续处理。
- 原有建筑图层和帧限制迁至外观配置；动画深度贴图使用对应的实际源帧，修复非零起始帧错位。

## 配置与支持边界

仓库现有配置编译出 409 个类型定义。解析定义不等于实现其全部能力。
现阶段可执行通用地面移动、单发抛射主武器、基础建筑与工厂、基地车转换。
`UnitTypeDef::unsupported` 标记目前识别出的不支持能力；它还不是所有 RA2 字段的完整兼容报告。

`rules.ini` 和 `art.ini` 保留原始字段。补充 INI 不重复保存生命值等游戏属性。
重复节按字段合并，后写字段覆盖前值；数值不接受 `400abc`、溢出或非有限值。
`IniDocument::overlay` 可编译规则覆盖，但尚未提供用户选择任意模组层的 UI。
配置只在场景创建时编译，修改后需重启。

配置摘要使用规范化内容的 FNV-1a，方便回归定位，不是安全哈希，也没有代替全部素材摘要。
当前配置摘要见 [速度实现](game-speed-implementation.md)。

下列仍采用明确的演示规则，不能宣称与原版一致：

- 移动/转向换算和炮弹飞行模型。速度档位与原始 ROF 已接入统一游戏帧，但这些运动参数尚需原版对照。
- 建筑施工/基地车转换的持续时间；显示动画按逻辑阶段映射，不由 GPU 动画回调控制完成。
- 每工厂独立队列、退出位置、立即预扣费用和取消全额退款。
- `Sandbox=no` 可验证基础资金/前置条件；尚无完整科技树、供电停机、原版生产分摊及建筑建造队列。
- 单位在厂内生成，通道按工厂配置预留；准备、驾驶、收尾阶段驱动生产图层，路径与时序尚未对照原版校准。
- 当前基础命中按锁定落点和整数距离结算；碰撞体、墙体/高低地、移动目标命中与溅射取整还需原版对照。
- 单主武器、单发抛射闭环；副武器、Burst、弹药、弹种目标过滤、自主寻敌、特殊能力仍需扩展。
- 建筑图层模板已迁移，维修、停靠、充能、断电等状态动画尚未拥有完整模拟驱动。
- 部分建筑图标目录及巨炮体素显示适配仍为既有资源适配代码，后续继续数据化。

## 性能基准与下一步

`RA2_BUILD_BENCHMARKS=ON` 构建 `ra2_simulation_benchmark`；参数为 settings 目录。
它分别测试 100/1,000/5,000 个实体，静止或同时下达短距离移动命令，运行 300 个逻辑 Tick。
输出平均/P95 耗时、完成数量与状态摘要，方便后续优化对比。

首批实现时本机 i9-12900H、MinGW Release 的一次观测如下；本轮出厂变更未重测，不是稳定性能门槛：

| 实体数 | 静止平均 ms/Tick | 移动命令平均 ms/Tick | 移动 P95 ms/Tick | 最终完成 |
| --- | --- | --- | --- | --- |
| 100 | 0.0041 | 0.0079 | 0.0097 | 100 |
| 1,000 | 0.0519 | 0.0884 | 0.1002 | 1,000 |
| 5,000 | 0.2473 | 0.4441 | 1.2188 | 5,000 |

这是无渲染、稀疏地图、短路径场景，不包含大规模交战、拥堵或 GPU 绘制，不能换算成游戏 FPS。
当前改进包括一次解析、资源按类型缓存和有预算的寻路调度；尚未实施 GPU 实例化/批处理优化。
工厂内部出车活动已接入；后续优先建立原版实测基线，并扩展集结点、停靠等能力，随后以基准指导图形性能优化。

## 单位一致性自检（2026-10-19）

结论：原版素材与基础规则数值已对齐，游戏行为仍属于部分兼容，不能以“能建造、能攻击”或 SupportStatus=Ready 认定已完全还原。此次原版基准是本地 assets_origin；没有启动纯净 RA2 1.006 二进制进行同场景逐帧／逐像素实验。OpenRA RA2 为另一套引擎和规则实现，Phobos 为 YR 原引擎补丁，二者都不能自动等同原版 RA2。

### 核对范围与证据

- 47 种可指挥单位：17 种步兵、16 种地面车辆、10 种海军、4 种空军；另检查 ASW / HORNET / V3ROCKET / DMISL 四类子机／导弹及 38 类已有素材的建筑／民居（其中一类为驻军民居）。不同图像别名按实际规则 ID 分开统计。
- 718 份运行时 SHP / VXL / HVA / PAL / TMP / VPL 均逐字节匹配 assets_origin；五份改名调色板也按内容找到原文件，无改绘或替代资源。原始 rules.ini / art.ini 只存在 CRLF / LF 换行差异。
- 89 个单位／建筑定义的 Strength、Cost、Speed、ROT、Armor、TechLevel 共 534 项一致。这仅证明字段导入，不能证明实际速度或状态机一致——本轮飞行速度问题正是“导入值正确、使用单位错误”。
- 75 个直接／分束／死亡／乘员武器的 1800 项字段检查，1799 项与原版一致。唯一显式转换为 ASWLauncher.Range=-2（原文件注明 infinite）被当前实现转成 100 格；普通 64 格地图通常不暴露差异，但不是严格无限，保留为待补项。检查包含 Damage、ROF、Range、MinimumRange、Speed、Burst、溅射、卧倒倍率、AA / AG 和 11 种护甲倍率；不代表所有已读取武器分支都已接入运行。
- 来源、数值清单、分区扫描、修复前失败记录、修复后日志和实际场景截图位于忽略目录 build/unit-audit；resource-audit.json、inventory.json、unit-findings.json、rule-fields.json、weapon-fields.json 为可查看的明细。

### 与开源实现的差异

本轮固定对照 OpenRA/ra2 `61e24e3c1d7b586aa55a86096d29e1559aa9b994`、OpenRA 引擎 `dde39344a0f25af15b039e6a2e4dbf046e624c04`、Phobos `c265252b21961345bfaebd3aa928fb721d166d74`、YRpp `a823ada387386a18ddadf41b4d7b46f295f94fdb`。没有运行这些外部引擎，也不以其最新分支替代固定版本证据。

| 项目 | 本地原版与本项目 | 固定版本 OpenRA RA2 | 判断 |
|---|---|---|---|
| 间谍生命 | 100 | 25 | OpenRA 自行平衡，保留本地原版值 |
| HORNET / ASW 弹药 | 1，出击一弹后返航 | 5 | 保留原版单弹流程 |
| 黄蜂弹伤害 | HornetBomb=40 | HornetBomb=80 | 保留原版伤害，不能按 OpenRA 再加倍 |
| 乌贼攻击 | 普通舰艇缠绕，Organic 目标拳击 | SQD 配置只有 SquidPunch | 本项目保留原版缠绕；原版硬编码周期仍需实测 |
| 超时空兵移动 | ChronoDistanceFactor / MinimumDelay 等按距离计算 | PortableChrono.ChargeDelay=300 | 保留原版距离恢复，不移植固定 300 tick 冷却 |
| 飞机机动／图像 | 原版 Jumpjet / FlightLevel 参数 + 自有整数状态机 | Aircraft / AttackAircraft / CarrierChild 等通用 trait | 可参考任务拆分；坐标、tick、速度标度和轨迹不能直接照搬 |
| 原版 bug 与扩展修正 | 以 RA2 行为为目标，未默认引入所有改动 | Phobos 修正／扩展 YR 的空中速度加成、Burst、转向等 | 必须区分原行为与补丁改进，不能将补丁公式当成未修改原版 |

### 建筑与共用系统的未完成项

- 基础建筑、兵营／战车工厂／机场／船厂、常规防御已具备建造、供电与对应基础功能；不代表全部规则标记已接入。维修厂 GADEPT / NADEPT 的地面车辆进厂维修尚未实现，当前已有建筑点修、维修 IFV、机场补给维修和船厂维修，几者不能混同。
- NANRCT 原版有 Explodes=yes、DeathWeapon=NukePayload、DeathWeaponDamageModifier=.5；现有定义对建筑未接通通用 DeathWeapon 流程，故核电站死亡核爆不等同原版。此项应与车辆／建筑死亡伤害统一处理。
- 光棱塔尚无完整支援串联网络；裂缝／卫星／心灵探测依赖的迷雾、地图可见性与预警覆盖未完成。超时空／天气／铁幕／核弹的完整超武充能与释放延续先前约定，本轮不把可建造等同于已开放超武能力。
- 目前自动索敌主要按武器范围扫描，Sight／GuardRange／CanRetaliate 尚未构成完整的警戒、受击反击和追击退出状态机。战斗经验与精英升级也未形成完整通路；间谍授予老兵后的若干基础加成并不等于完整经验系统。
- 兵种状态机以确定性整数近似为主。步兵身体半径、恐惧／恢复、碾压半径、幻影闪烁、通用死亡伤害、乌贼周期等已有明确兼容值，缺少原版同场景测量。

建议后续顺序：先补受击反击／警戒追击与老兵精英，再补维修厂和核电站死亡武器；随后做海空机动、乌贼／海豚、光束与伪装的原版逐帧校准。声音、碎片、震屏和完整环境破坏单独收尾；超武按用户后续范围安排。
